# 基礎設施管理系統 infra-manager

## 基本架構

- 一個api
- 一個管理介面
- api經過token驗證後反向代理到目標服務，攜帶所有請求header、body、查詢參數
  - 用戶或token若被停權、token過期或無效或與請求的服務不符則回傳403
  - 找不到服務則回傳404
- 代理路徑：
  - 網址 token：`/use/<服務名稱>/<存取token>/<目標路徑>`，原有 `/api/` 路徑仍可使用。
  - Bearer token：`/use/<服務名稱>/<目標路徑>`，標頭帶 `Authorization: Bearer <存取token>`。
  - 辨識為網址 token 時優先驗證網址 token，即使無效、停用或過期也不會改用 Bearer。辨識方式是 32 碼小寫十六進位字串，或資料庫中曾存在的 token；目標路徑第一段若符合這些條件，也會被視為網址 token。
  - 若目標路徑第一段被誤認為網址 token，另帶 `X-Infra-Token-Source: bearer`，明確指定使用 Bearer。
  - Authorization 標頭會照原樣轉送到後端服務。
- 管理介面只有一個admin，人員都是由admin管理，admin密碼由環境變數設定

## 技術棧

- 前端：HTML + CSS + JS，使用Ajax
- 後端：Gin + Gorm
- 路由：Gin，但不使用模板引擎
- 資料庫：SQLite3
- 部署：Docker + Docker Compose

## 使用 Docker Compose 啟動

1. 複製範例設定：`cp .env.example .env`。
2. 修改 `.env` 的 `DATA_DIR`，指定 Docker 主機上的資料目錄。既有部署請使用原本的 `/mnt/hdd0/infra-manager/data`，並確認其中有原本的 `infra_manager.db`。
3. 確認外部 Docker 網路 `infra-net` 已存在。
4. 執行 `docker compose config --quiet` 檢查設定，再執行 `docker compose up -d --build` 啟動。

`DATA_DIR` 未設定或為空時，Compose 不會正常啟動。指定的目錄不存在時 Docker 會自動建立；路徑錯誤可能導致程式建立新的空資料庫，請在啟動前確認路徑。`.env` 不納入版本控制。

## 對應關係

- 一個人員可以有多個token
- 一個token只能對應一個人員
- 一個token只能對應一個服務
- 一個服務可以對應多個token

## 管理介面功能

### 管理

- 新增/修改/刪除/停權人員
- 新增/修改/刪除/停權token
- 新增/修改/刪除/停權服務

### 視覺化儀表板

儀表板顯示已啟用的使用者、服務、有效 Token，以及 7 天內到期的 Token。頂端搜尋可查使用者、服務與 Token 備註；到期清單可直接開啟 Token 編輯。

可選擇最多 90 天的日期範圍，查看該期間已通過驗證的請求與服務使用情況，日期以台北時間計算。正常回應是 HTTP 100–399，錯誤回應是 400 以上；此分類不代表內容一定傳送完成，傳輸中斷與驗證失敗請到失敗紀錄查詢。服務表格的使用者與 Token 數是期間內有使用的不同數量。下方詳細圖表以 UTC 日期計算，不受上方自訂日期影響。


- 每個人員每種服務使用量圓餅圖、長條圖、折線圖
- 每個人員每個token使用量圓餅圖、長條圖、折線圖
- 每個token隨時間使用量折線圖
- 每個服務隨時間使用總量折線圖
- 每個服務使用總量圓餅圖、長條圖


服務可以填寫選用的類型，未填寫時顯示「未設定」。儀表板每日保存一筆當天首次成功觀測的四項數量，與上月同日的觀測比較。每日摘要最多保留 90 筆且最多保留 90 個台北日，未曾觀測的日期顯示「無歷史資料」，不回填停機期間或啟用前的數值。月底沒有對應日期時使用上月最後一天。

### 失敗紀錄與資料保留

管理介面提供失敗紀錄查詢，可依失敗類型、服務、HTTP 回應碼及日期篩選，並逐頁查看。失敗紀錄區分驗證、本機處理、上游連線、上游回應與來源未確認的傳輸中斷，並分別顯示本系統及上游回應碼。新功能啟用前的失敗無法回補。

失敗紀錄最多保留 90 天及 100,000 筆，使用紀錄最多保留 90 天及 1,000,000 筆。達到筆數上限時會刪除最舊紀錄，因此高流量時可能不足 90 天；舊紀錄刪除後，使用量圖表不再包含這些資料。程式啟動時及執行中每天清理過期紀錄，新增紀錄時也套用筆數上限。新使用紀錄的路徑最多保留 512 個字元，方法最多保留 32 個字元。

SQLite 清理後會重用空間，現有資料庫檔案不一定立即縮小。筆數限制不是整個資料庫檔案的硬性容量上限，其他資料、索引和交易暫存仍會占用空間。
